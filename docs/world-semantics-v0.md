# Kadmos World v0: Observed Semantics

This documents the K-02 compiler contract `kadmos.compiler.k02.v1` implemented on 2026-10-09 from manifest version 0.1.2. It is a reference for using and testing the implementation, not a proof that a World captures domain intent or that Fabric implements it. [Conformance tests](../tests/test_world_semantics_conformance.test.ts) execute interpreted TypeScript, emitted TypeScript, and emitted Python against independent expected outcomes.

## Model admission

`parseWorldSpec` in `src/world_compiler.ts` accepts a restricted indentation-based YAML subset. It does not accept inline mapping values such as `{ type: integer }`. It requires version `kadmos.world.v0`, one initial state, unique state IDs and transition IDs, declared transition endpoints, and no outgoing transition from a terminal state. Optional state `initial` and `terminal` markers must be exact booleans when supplied; absence and an own JavaScript `undefined` remain permitted. Null, strings, numbers, objects, and arrays are refused before initial-state selection or terminal-edge checks. Context fields are `integer` or `string`; integer bounds and defaults must be JavaScript safe integers, an explicit minimum cannot be negative, an omitted integer default is 0, and a string field requires a string default without numeric bounds. Declared identifiers are checked in expressions, but parsing does not prove all expressions well typed or all reachable states safe.

World source `directive` may be omitted, `directive:` (YAML empty scalar), explicit `null`, or a nonempty string. The first three normalize to canonical null and authorize no directive. An own JavaScript `undefined`, empty string, or wrong primitive/object type is rejected with `INVALID_WORLD: directive`; empty-string rejection tightens the former parser behavior. The same `admitWorldSpec` boundary validates parsed YAML and programmatic models before compilation or interpreted checker creation. It rejects proxies and accessors before reading model fields, and rejects callable, symbol, bigint, and nonfinite numeric leaves without invoking serialization or coercion hooks. Explicit `undefined` values in optional model fields remain permitted. Data-only class instances with own fields remain admissible; inherited fields are not read. Transition endpoints must be strings before undeclared-state diagnostics are formatted. Every invariant requires a nonempty string `id`; malformed IDs are refused before a checker can evaluate its predicate. `context: {}`, `invariants: []`, and `transitions: []` are valid when explicitly present; missing required collections are rejected. An empty invariant list adds no synthetic tautology. This World field is distinct from the optional **request** field `proposedDirective`: omitting the request field matches canonical null, while omitting it for `SEND` is refused with `UNAUTHORIZED_DIRECTIVE`.

## Expression evaluation

`src/world_expression.ts` and the emitted evaluators tokenize single-quoted strings, booleans, null, decimal numerals, identifiers and property paths; support parentheses, unary `!`/`-`, arithmetic, comparisons, equality, `&&`, `||`, and implication `=>`; and use precedence climbing. Implication associates to the right. `&&`, `||`, and `=>` evaluate both operands and require exact booleans; they do not short-circuit. A missing property or property access through a falsy base evaluates to null. Guards and invariants must evaluate to exact boolean `true`; false, another type, or an evaluation error refuses the step.

Numeric expression operations use JavaScript/IEEE-754 number behavior. Division by zero can produce infinity or NaN; equality can compare such values without an automatic refusal (`1 / 0 == 1 / 0` is true in both emitted checkers). A later numeric operator that requires a finite operand, or an integer effect/context check, can refuse a nonfinite value. Python's generated evaluator normalizes numeric expression operands to float64 and has matching division behavior in the tested cases. Do not assume all arithmetic is exact integer arithmetic merely because a context field is declared `integer`.

## Step order and admission

The request fields are `transitionId`, optional `eventPayload`, and optional `proposedDirective`; `payload` is not an alias. The checker validates request shape and primitive field types, then sanitizes `eventPayload`. The TypeScript sanitizer rejects proxies, non-plain objects, accessors, arrays, functions/symbols, cycles/shared object nodes, excessive depth/node count, and reserved keys `__proto__`, `constructor`, and `prototype`. Python requires an exact dict request and similarly limits payload structure and reserved keys. Payload booleans, fractions and unsafe numeric values are copied as primitives; payload sanitization alone does **not** require every number to be a safe integer. A malformed primitive request field returns `SECURITY_VIOLATION`; an integer context reset or effect receiving the wrong type or an unsafe integer is rejected at that later stage.

For a valid request, the checker finds a transition from the current state, compares the proposed directive exactly with the World directive, evaluates the guard in the source state, evaluates effects **in listed order** against a candidate context and destination state, checks each effect's target type, then checks context bounds and all post-state invariants. Later effects see earlier candidate updates: with defaults `a=2,b=0`, effects `a = a + 1; b = a + 1` yield `a=3,b=4`. An accepted step publishes state/context/history and returns the declared `directiveAllowed`. A refused step leaves checker state, context and accepted history unchanged and returns null `directiveAllowed` with a violation. Terminal-state attempts are refused.

The response property `shortestCounterexampleTrace` contains the accepted step prefix plus the refused attempt. It is an ordered diagnostic witness, not a proof of a globally shortest path. A refusal after one accepted step has two records; the refused attempt does not enter accepted history. All three checkers accept optional constructor context. Omitted or null/None resolves World defaults; a plain object overlays them, passes strict type/bounds and initial-invariant checks, and becomes the private resolved constructor seed. Bare `reset()` or explicit null/None restores that seed. Explicit `reset({})` restores World defaults; any other explicit object overlays World defaults without changing the seed. Malformed non-null shapes fail `INVALID_BOUNDS` before key enumeration. Failed reset leaves state/context/history and the earlier savepoint intact; successful reset clears accepted history and savepoint.

## Rollback and concurrent Fabric

Interpreted and emitted TypeScript expose `rollbackLastStep()` in both class and `IWorldChecker`; emitted Python exposes `rollback_last_step()` in class and Protocol. It restores the state/context/accepted-history snapshot immediately before the **most recent successful** step and consumes that one savepoint. It raises `NO_CHECKER_SAVEPOINT` if absent or busy. A rejected step, exception, or failed reset preserves an earlier savepoint; a later success replaces it; successful reset clears it. Never call rollback after a refusal alone, because it could undo earlier accepted work. Internal rejection rollback is separate. Python's public `state`, `context`, and `history` remain readable, but writes raise `AttributeError` and context/history reads return copies. Python introspection can still reach mangled backing fields; this is not adversarial-process isolation.

The checker is synchronous and guards reentrant evaluation, but it does not serialize physical work across `await`. Fabric sharing a checker must serialize step, physical effect, and possible rollback as one operation. Checker rollback only changes in-memory checker state. It cannot undo a committed database write, API call, or cross-process effect; those need separate transactional, idempotent, or compensating design.

## Verification scope and limits

`kadmos test` in `src/fuzzer.ts` uses seeded requests to compare an **interpreted TypeScript checker** with a **generated Python checker** on selected verdict fields and sampled traces. Passing runs are empirical differential evidence, not a proof of all-input bisimulation and not correspondence of emitted target code to the World. The tests named above additionally execute emitted TypeScript and Python against independent expected outcomes. Runtime invariant refusal for checked requests is narrower than model-wide reachability proof.

Strict emitted TypeScript typechecks and Python imports cover empty context, invariant, transition, and directive sets. Three-path fixed traces cover accepted/refused transitions, ordered effects, directive presence, violation messages/history, constructor/reset, and rollback. These are finite empirical checks, not a compiler-correctness or bisimulation proof. The compiler contract marker is human-readable; an immutable source commit identifies the exact implementation for a later Harmonia pin.
