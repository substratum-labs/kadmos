# Kadmos World v0: Observed Semantics

This documents behavior in source version 0.1.2 as of 2026-10-08. It is a reference for using and testing the current implementation, not a proof that a World captures domain intent or that Fabric implements it. The generated TypeScript and Python checkers are projections from the World; they have differences and known defects listed below. [Conformance tests](../tests/test_world_semantics_conformance.test.ts) execute both emitted checkers with fixed expected results.

## Model admission

`parseWorldSpec` in `src/world_compiler.ts` accepts a restricted indentation-based YAML subset. It does not accept inline mapping values such as `{ type: integer }`. It requires version `kadmos.world.v0`, one initial state, unique state IDs and transition IDs, declared transition endpoints, and no outgoing transition from a terminal state. Context fields are `integer` or `string`; integer bounds and defaults must be JavaScript safe integers, an explicit minimum cannot be negative, an omitted integer default is 0, and a string field requires a string default without numeric bounds. Declared identifiers are checked in expressions, but parsing does not prove all expressions well typed or all reachable states safe.

Every usable transition should explicitly declare `directive`, using `directive: null` when it authorizes no directive. The parser currently accepts an omitted World directive without supplying null, which leads to the defects below. This World field is distinct from the optional **request** field `proposedDirective`: omitting the request field matches an explicitly null World directive, while omitting it for a World directive such as `SEND` is refused with `UNAUTHORIZED_DIRECTIVE`.

## Expression evaluation

`src/world_expression.ts` and the emitted evaluators tokenize single-quoted strings, booleans, null, decimal numerals, identifiers and property paths; support parentheses, unary `!`/`-`, arithmetic, comparisons, equality, `&&`, `||`, and implication `=>`; and use precedence climbing. Implication associates to the right. `&&`, `||`, and `=>` evaluate both operands and require exact booleans; they do not short-circuit. A missing property or property access through a falsy base evaluates to null. Guards and invariants must evaluate to exact boolean `true`; false, another type, or an evaluation error refuses the step.

Numeric expression operations use JavaScript/IEEE-754 number behavior. Division by zero can produce infinity or NaN; equality can compare such values without an automatic refusal (`1 / 0 == 1 / 0` is true in both emitted checkers). A later numeric operator that requires a finite operand, or an integer effect/context check, can refuse a nonfinite value. Python's generated evaluator normalizes numeric expression operands to float64 and has matching division behavior in the tested cases. Do not assume all arithmetic is exact integer arithmetic merely because a context field is declared `integer`.

## Step order and admission

The request fields are `transitionId`, optional `eventPayload`, and optional `proposedDirective`; `payload` is not an alias. The checker validates request shape and primitive field types, then sanitizes `eventPayload`. The TypeScript sanitizer rejects proxies, non-plain objects, accessors, arrays, functions/symbols, cycles/shared object nodes, excessive depth/node count, and reserved keys `__proto__`, `constructor`, and `prototype`. Python requires an exact dict request and similarly limits payload structure and reserved keys. Payload booleans, fractions and unsafe numeric values are copied as primitives; payload sanitization alone does **not** require every number to be a safe integer. A malformed primitive request field returns `SECURITY_VIOLATION`; an integer context reset or effect receiving the wrong type or an unsafe integer is rejected at that later stage.

For a valid request, the checker finds a transition from the current state, compares the proposed directive exactly with the World directive, evaluates the guard in the source state, evaluates effects **in listed order** against a candidate context and destination state, checks each effect's target type, then checks context bounds and all post-state invariants. Later effects see earlier candidate updates: with defaults `a=2,b=0`, effects `a = a + 1; b = a + 1` yield `a=3,b=4`. An accepted step publishes state/context/history and returns the declared `directiveAllowed`. A refused step leaves checker state, context and accepted history unchanged and returns null `directiveAllowed` with a violation. Terminal-state attempts are refused.

The response property `shortestCounterexampleTrace` currently contains the accepted step prefix plus the refused attempt. It is an ordered diagnostic witness, not a proof of a globally shortest path. A refusal after one accepted step has two records; the refused attempt does not enter accepted history. Reset validates a candidate initial context and initial-state invariants before publishing, and a failed reset leaves current state/context/history intact.

## Rollback and concurrent Fabric

The generated TypeScript class has `rollbackLastStep()`. It restores the state/context/history snapshot immediately before the **most recent successful** step and consumes that one savepoint. It throws `NO_CHECKER_SAVEPOINT` if no savepoint is available or while busy. A rejected step does not consume a prior savepoint, so invoking rollback after refusal can wrongly undo earlier accepted work. A later successful step replaces the savepoint; a successful reset clears it. The interpreted checker in `src/world_checker.ts` and the generated Python checker expose no corresponding post-success rollback method. Their internal rejection rollback is a different operation.

The checker is synchronous and guards reentrant evaluation, but it does not serialize physical work across `await`. Fabric sharing a checker must serialize step, physical effect, and possible rollback as one operation. Checker rollback only changes in-memory checker state. It cannot undo a committed database write, API call, or cross-process effect; those need separate transactional, idempotent, or compensating design.

## Verification scope and known deficiencies

`kadmos test` in `src/fuzzer.ts` uses seeded requests to compare an **interpreted TypeScript checker** with a **generated Python checker** on selected verdict fields and sampled traces. Passing runs are empirical differential evidence, not a proof of all-input bisimulation and not correspondence of emitted target code to the World. The tests named above additionally execute emitted TypeScript and Python against independent expected outcomes. Runtime invariant refusal for checked requests is narrower than model-wide reachability proof.

Known deficiencies, kept separate from intended semantics:

1. **Omitted World directive.** Parsing accepts it. The emitted TypeScript source fails strict typecheck because some transition objects lack `.directive`; if emitted despite diagnostics, a no-directive request returns `UNAUTHORIZED_DIRECTIVE` because `null !== undefined`. The generated Python `ports.py` is syntactically invalid (`Literal[]` or `Literal[, ...]`), so normal import fails before `step()`. If that port failure were bypassed, the generated step reads `transition["directive"]` and would raise `KeyError`. The conformance test retains the actual compile/import witness. Normal Worlds and fixtures use explicit null; generators are not patched here.
2. **Empty invariant list.** Emitted TypeScript currently fails strict typecheck because iteration over a literal empty `world.invariants` infers `never` for invariant entries. Ordinary executable fixtures in this suite include a real invariant. This is not fixed by inventing a tautological semantic requirement that all Worlds have invariants.
3. **Rollback interface asymmetry.** The emitted TypeScript class has `rollbackLastStep()` but its generated `ports.d.ts` `IWorldChecker` omits it; generated Python and interpreted TypeScript lack a public post-success equivalent. No cross-language rollback parity is claimed.

Any behavior change to these generators needs its own reviewed regression and regenerated seams. The current document records what was observed rather than silently broadening accepted Worlds or promising future behavior.
