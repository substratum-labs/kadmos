## Implemented contract and compatibility

`admitWorldSpec` is the shared boundary for parsed YAML, direct compiler inputs, and the interpreted checker. An omitted World directive and YAML `directive:`/`directive: null` become canonical null. Explicit nonempty strings remain exact authorizations. An own JavaScript `undefined`, empty string, wrong primitive or object fails `INVALID_WORLD: directive`; rejecting the empty string is an intentional tightening. Proxy and accessor model inputs are rejected before model field reads, with zero-call getter/trap regressions. Callable, symbol, bigint, and nonfinite numeric leaves are rejected as non-data/non-JSON input before serialization; optional own fields with `undefined` remain permitted. Transition endpoints must be strings before error formatting, invariant IDs must be nonempty strings before checker construction, and optional state `initial`/`terminal` markers must be booleans when supplied. Absent and own `undefined` state markers remain valid; null, strings, numbers, objects, and arrays are refused before initial selection or terminal-edge checks. Programmatic models with data-only own fields remain admissible even when supplied as class instances; inherited fields are not read. YAML mapping keys are constructed as own data properties, and emitted TypeScript parses the admitted World/default context as JSON into structural readonly types. Thus an admitted context key `__proto__` is retained as data rather than triggering JavaScript object-literal prototype semantics; event payload sanitizer rules are unchanged. Explicit empty context, invariant, and transition collections compile without a synthetic invariant; missing required collections fail admission.

Interpreted and emitted TypeScript and emitted Python now accept optional nullable constructor context, remember the resolved constructor seed, and restore it on bare/null/None reset. An explicit object overlays World defaults without replacing the seed; explicit `{}` selects defaults. Invalid non-null shapes or values fail `INVALID_BOUNDS` before enumeration. Successful reset clears the savepoint; refusal, exception, and failed reset preserve it. An accepted step replaces the single pre-success state/context/accepted-history snapshot; rollback consumes it, with stable `NO_CHECKER_SAVEPOINT` when absent or busy. Source/emitted TS interfaces declare `rollbackLastStep()`, and the Python Protocol declares `rollback_last_step()`.

Python `state`, `context`, and `history` remain readable properties, while direct writes raise `AttributeError` and context/history reads are copies. This changes unsupported live-field mutation behavior: `examples/job-queue-benchmark/python_worker.py` now invokes `rollback_last_step()` immediately after an allowed step's physical effect fails, before Redis compensation. Python introspection can reach mangled attributes; checker rollback cannot undo external writes. The existing valid World fixtures, request keys, seeded fuzzer API/report, package dependency list, and generated zero-dependency requirement remain intact.

Pure malformed endpoint values `{}` and `0` receive `INVALID_WORLD: transition endpoint` without string coercion, while an undeclared string endpoint retains `UNDECLARED_STATE`. Missing, empty-string, and numeric-zero invariant IDs each receive `INVALID_WORLD: invariant id` at all four entrypoints; a well-formed `BLOCK` ID with predicate `false` still raises `INITIAL_INVARIANT_FAILED: BLOCK` in interpreted TS, emitted TS, and emitted Python. True, false, absence, and own `undefined` stay admissible; an actual `terminal: true` state still refuses an outgoing transition with `TERMINAL_STATE`.

1. The prior omitted-directive conformance test asserted the defect that Task 1 repaired. It was converted to a positive TS/Python acceptance regression during Task 2 so that its required focused suite could pass; Task 4 then added the independent full-outcome runner. Cost if wrong: an insufficient oracle could hide shared errors; fixed literal outcomes now check all three paths separately.
2. The BullMQ adapter's checked-in `ports.ts` is a renamed copy of generated `ports.d.ts`. It was refreshed from canonical CLI output without handwritten seam changes. Cost if wrong: a future regeneration that updates only `ports.d.ts` would leave the adapter stale; the mapping is recorded above.
3. A final compatibility probe showed that a blanket prototype check rejected programmatic Worlds with data-only own fields. It was removed after a RED/GREEN test; proxy and accessor rejection still precedes reads. Inherited model fields remain unread. Cost if wrong: applications relying on inherited required fields must move them to own data fields.
4. Parent probes found callable leaves could reach generator serialization and malformed endpoints could invoke caller `toString`; falsy malformed invariant IDs could suppress a real failed invariant. The shared admission boundary now rejects those non-canonical inputs before checker/generator use. This intentionally tightens unsupported model metadata while preserving optional own `undefined` fields and data-only class instances. Cost if wrong: callers storing functions, symbols, bigints, or nonfinite numbers in arbitrary World metadata must remove them from the pure-data IR.
5. Parent finding 4 showed malformed state markers could bypass the exact-true initial count or terminal-edge rule through later truthiness checks. Admission now rejects supplied non-Boolean markers before both existing algorithms. This is a canonical required-type tightening; the algorithms and empty-state-name/duplicate policy were not expanded. Cost if wrong: callers using truthy string/number markers must provide actual booleans.
6. Finding 5 was a representation mismatch for an already admitted pure-data context name. Preserved the field by defining YAML map entries as own properties and parsing serialized World/default data in emitted TS with an explicit structural type. This avoids a new reserved-name policy and leaves event-payload reserved-key refusal intact. Cost if wrong: generated TS World tables now rely on JSON parsing at module initialization; strict NodeNext, all three runtime paths, the packed consumer, and adapter tests exercise that path.
7. No new Python physical-failure code fence was added to README or the copied Skill. The tested benchmark worker exercises the real Python rollback path; the Skill describes the method and limits in prose, avoiding an unexecuted displayed example.
