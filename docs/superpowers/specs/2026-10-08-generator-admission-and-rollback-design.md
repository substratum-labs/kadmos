## Admission and canonical model

The source World transition field `directive` may be omitted, written as YAML `directive:` (an empty scalar), or explicitly `null`; all three mean **no directive is authorized**. An explicit nonempty string authorizes exactly that string. This is the smallest compatible repair: existing explicit-null/string Worlds retain their meaning and previously parsed omitted-field Worlds become executable. Rejecting omission would break previously admitted Worlds. An explicitly present JavaScript `undefined`, number, boolean, object, array, or empty string fails `INVALID_WORLD: directive`. Empty-string rejection tightens admission relative to the current raw-cast parser, which accepts it without a useful directive meaning. At runtime a request with no `proposedDirective` or explicit null matches a null World directive; wrong strings and malformed request primitives retain their present refusal stages. Source normalization never coerces malformed runtime requests.

One exported `admitWorldSpec(raw: unknown): WorldSpec` in new `src/world_admission.ts` validates and creates a fresh canonical model. `src/world_compiler.ts` re-exports it. `parseWorldSpec` calls it after YAML parsing; `compileWorldSpec`, `compileWorldSpecPython`, and `createWorldChecker` call it for directly supplied models. The separate module avoids a compiler/re-export cycle. No caller may rely on a TypeScript cast to bypass admission. Split types in `src/types/world.ts`: `WorldSpecInput`/`TransitionDefInput` permit omitted source directives, while canonical `WorldSpec`/`TransitionDef` require `directive: string | null`. Existing valid programmatic `WorldSpec` values remain assignable to input parameters. Admission first rejects Node proxies, then inspects own property descriptors at every object layer and rejects getters/setters before reading `.directive`, `.id`, `.effects`, or any other field. Direct validation must never run an accessor. YAML parsing receives a string and produces plain data; its test checks unchanged source input, without inventing YAML getters. The normalized output owns its objects and arrays; callers cannot mutate an admitted model after compilation or checker creation. The shared validator retains current v0 checks for version, one initial state, unique state/transition IDs, endpoints, terminal outgoing edges, context definitions, expression identifiers, guards, effects, and required arrays. It must reject malformed direct inputs before any generator can emit code. Do not expand YAML syntax or silently default missing lists/context.

`invariants: []` is a valid empty conjunction. Do not synthesize a `true` invariant. Explicit `context: {}`, `invariants: []`, `transitions: []`, and an initial state without outgoing transitions are valid under existing parser rules; missing context or required lists are invalid. At least one state and exactly one initial state remain required. Emitted TS must widen empty-array iteration sites that otherwise infer `never`, including invariants and transitions. Python `WorldDirective` with zero names must be a valid `None` type alias, not `Literal[]`; one or more names use a valid `Literal[...]`. Both emitted Python files must import on Python 3.10–3.13. TS projection must pass strict NodeNext typecheck for these edge Worlds.

## One-step savepoint contract

All three checkers expose one public rollback operation: interpreted and emitted TS `rollbackLastStep(): void`, Python `rollback_last_step() -> None` in class and emitted `IWorldChecker` Protocol. The source `IWorldChecker` and emitted `ports.d.ts` both declare the TS method. Keep the existing Python `getState`/`getContext` compatibility aliases; do not require a camelCase rollback alias.

All three paths accept an optional constructor context: interpreted `createWorldChecker(world, initialContext?: Partial<WorldContext> | null)`, emitted TS `new WorldChecker(initialContext?: Partial<WorldContext> | null)`, and Python `WorldChecker(initial_context: dict[str, int | str] | None = None)`. Omitted or explicit null/None constructor input resolves to World defaults. A supplied plain context object overlays World defaults, with strict field type/bound checks and initial-state invariant evaluation. Each checker privately remembers the **resolved constructor context** as its reset seed. Bare `reset()` and explicit `reset(null)`/`reset(None)` restore that seed. Explicit `reset({ ... })` overlays the object on World defaults and does not change the remembered seed; `reset({})` therefore restores World defaults, which may differ from the constructor seed. Thus constructor `{n: 2}`, successful `reset({n: 4})`, then bare reset yields `n=2`. This nullable absence variant retains Python's documented Optional/None behavior and avoids a new sentinel. It intentionally changes emitted TS bare-reset behavior when constructed with a custom context, aligning it with interpreted TS and Python. Rejecting null would break Python `reset(None)`; mapping null only in a test runner would conceal a real API split.

Before enumerating keys, TS constructor/reset reject arrays, scalar booleans/numbers/strings, proxies, accessors, and non-plain objects with `INVALID_BOUNDS`; accepted plain records have `Object.prototype` or null prototype and own data properties. Python accepts only exact `dict` or None and continues strict primitive checks (`bool` is not an integer). Values are copied before storage. Invalid constructor/reset context or failed initial invariant raises `INVALID_BOUNDS` or `INITIAL_INVARIANT_FAILED`, respectively, without publishing candidate state, changing the seed, or consuming an earlier savepoint. These stable prefixes are defined before runner implementation; unknown exceptions are rethrown.

The savepoint is the private deep copy of state, context, and **accepted** history immediately before the most recent successful step. A success replaces any earlier savepoint. Refusal, evaluation exception, or failed reset leaves the earlier savepoint intact. Successful reset clears it. Rollback restores the saved triple and consumes the savepoint; a second rollback, rollback before any success, or rollback after successful reset raises `NO_CHECKER_SAVEPOINT` (`Error` in TS, `RuntimeError` in Python). While evaluation is busy, rollback raises the same stable `NO_CHECKER_SAVEPOINT` and does not consume a savepoint. Constructor's initial reset must not create one; invalid constructor context or initial invariant failure must not publish a checker/savepoint. Reentrant payload tricks must never publish or consume a savepoint. Internal refusal rollback is separate from this public operation.

Interpreted TS uses a closure-private savepoint; emitted TS retains ECMAScript `#private` state. Generated Python uses double-underscore backing fields for state, context, accepted history, reset seed, and savepoint. Its existing public `state`, `context`, and `history` names become read-only properties; context/history return deep copies, and assignments raise `AttributeError`. Existing getters and aliases remain. `examples/job-queue-benchmark/python_worker.py` currently assigns those three fields after an accepted step's physical failure; replace that restoration block with `rollback_last_step()` and test the worker path. Existing Python tests that intentionally mutate live public fields become property/copy-isolation tests while retaining hostile rejection probes. Writable live fields are incompatible with the intended checker-state protection. Python introspection can still access mangled fields; do not advertise introspection-proof or adversarial-process isolation. Return copies and private savepoints prevent ordinary Fabric code from mutating saved history. The method changes checker memory only. A physical failure *after an allowed step* calls rollback immediately; refusal never calls it. Serialize the whole `step → physical effect → possible rollback` window per checker. External writes need independent transaction, compensation, or idempotency handling.

## Three-path conformance and empirical fuzzing

Use a small reusable test runner for commands `step(request)`, `reset(context?)`, `rollback`, `getState`, and `getContext`, with separate optional `initialContext`. It instantiates each of the three checkers from the same admitted World, compiles emitted TS under strict NodeNext, imports emitted Python, and runs identical command sequences. For reset commands, own absence of `context` means bare reset, while an own `context: null` calls the explicit nullable API on all paths; both restore the seed. An object means explicit World-default overlay; malformed non-null values are tested directly. Normalize observations to kind, full verdict, post-command state/context, or known stable error prefix. A normalized verdict contains allowed, previous/current state, context, directiveAllowed, and optional violation with code, message, optional violatedInvariant, and ordered `shortestCounterexampleTrace`; each record preserves own presence of `eventPayload` and `proposedDirective`. Compare each path separately with a hand-authored expected sequence, including exact diagnostic message and trace payload/directive field presence. Do not pretend `Error`, `ValueError`, and `RuntimeError` are the same class, and rethrow unknown exception text. The `shortestCounterexampleTrace` name remains an ordered witness, not a globally shortest-path proof.

Fixtures include: omitted/explicit-null/nonempty-string directives; no directive names; explicitly empty invariants/context/transitions; sequential effects; guard, bounds, and invariant refusals; wrong and absent directives; constructor `{n: 2}` followed by step, explicit `reset({n: 4})`, bare reset to 2, and consumed savepoint; explicit `reset(null)`/`reset(None)`; successful step followed by refusal and failed reset; multiple successes replacing savepoint; rollback consumed; invalid constructor; malformed top-level constructor/reset shapes; malformed programmatic models; primitive and hostile request/payload cases. Change old characterization tests that assert generator defects to regression acceptance tests. The existing `kadmos test` seeded flags/report stay compatible. Extend its coverage only where a small shared command/verdict normalizer improves comparison; fixed expected fixtures are the primary oracle. Finite deterministic traces and fuzz samples are empirical evidence, not a bisimulation or compiler-correctness proof.
