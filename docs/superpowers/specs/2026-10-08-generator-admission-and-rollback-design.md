## Admission and canonical model

The source World transition field `directive` may be omitted or explicitly `null`; both mean **no directive is authorized**. An explicit string authorizes exactly that string. This is the smallest compatible repair: existing explicit-null/string Worlds retain their meaning and previously parsed omitted-field Worlds become executable. Rejecting omission would be fail-closed but break those admitted Worlds, including programmatic callers. No malformed non-null value is normalized: number, boolean, object, array, and `undefined` when present explicitly fail `INVALID_WORLD: directive`. Empty string also fails because it is not a meaningful directive identifier. At runtime a request with no `proposedDirective` or explicit null matches a null World directive; wrong strings and malformed request primitives retain their present refusal stages.

One exported `admitWorldSpec(raw: unknown): WorldSpec` in new `src/world_admission.ts` validates and creates a fresh canonical model. `src/world_compiler.ts` re-exports it. `parseWorldSpec` calls it after YAML parsing; `compileWorldSpec`, `compileWorldSpecPython`, and `createWorldChecker` call it for directly supplied models. The separate module avoids a compiler/re-export cycle. No caller may rely on a TypeScript cast to bypass admission. Split types in `src/types/world.ts`: `WorldSpecInput`/`TransitionDefInput` permit omitted source directives, while canonical `WorldSpec`/`TransitionDef` require `directive: string | null`. Existing valid programmatic `WorldSpec` values remain assignable to input parameters. The normalized output owns its objects and arrays; callers cannot mutate an admitted model after compilation or checker creation. The shared validator retains current v0 checks for version, one initial state, unique state/transition IDs, endpoints, terminal outgoing edges, context definitions, expression identifiers, guards, effects, and required arrays. It must reject malformed direct inputs before any generator can emit code. Do not expand YAML syntax or silently default missing lists/context.

`invariants: []` is a valid empty conjunction. Do not synthesize a `true` invariant. `context: {}`, `transitions: []`, and an initial state without outgoing transitions are valid under existing parser rules; at least one state and exactly one initial state remain required. The emitted TS invariant loop must use a widened readonly invariant view so an empty literal does not infer `never`. Python `WorldDirective` with zero names must be a valid `None` type alias, not `Literal[]`; one or more names use a valid `Literal[...]`. Both emitted Python files must import on Python 3.10–3.13. TS projection must pass strict NodeNext typecheck for these edge Worlds.

## One-step savepoint contract

All three checkers expose one public rollback operation: interpreted and emitted TS `rollbackLastStep(): void`, Python `rollback_last_step() -> None` in class and emitted `IWorldChecker` Protocol. The source `IWorldChecker` and emitted `ports.d.ts` both declare the TS method. Keep the existing Python `getState`/`getContext` compatibility aliases and constructor/reset behavior; do not require a camelCase rollback alias.

The savepoint is the private deep copy of state, context, and **accepted** history immediately before the most recent successful step. A success replaces any earlier savepoint. Refusal, evaluation exception, or failed reset leaves the earlier savepoint intact. Successful reset clears it. Rollback restores the saved triple and consumes the savepoint; a second rollback, rollback before any success, or rollback after successful reset raises `NO_CHECKER_SAVEPOINT` (`Error` in TS, `RuntimeError` in Python). While evaluation is busy, rollback raises the same stable `NO_CHECKER_SAVEPOINT` and does not consume a savepoint. Constructor's initial reset must not create one; invalid constructor context or initial invariant failure must not publish a checker/savepoint. Reentrant payload tricks must never publish or consume a savepoint. Internal refusal rollback is separate from this public operation.

Interpreted TS uses a closure-private savepoint; emitted TS retains ECMAScript `#private` state. Python keeps its existing `state`, `context`, `history`, and `_busy` attributes for source compatibility, but stores the new savepoint in a double-underscore field and deep copies it. Existing tests and adapters directly inspect those Python attributes, so replacing them with inaccessible fields is a separate API change. Return copies and history snapshots must prevent Fabric mutation of saved records. The method changes checker memory only. A physical failure *after an allowed step* calls rollback immediately; refusal never calls it. Serialize the whole `step → physical effect → possible rollback` window per checker. External writes need independent transaction, compensation, or idempotency handling.

## Three-path conformance and empirical fuzzing

Use a small reusable test runner for commands `step(request)`, `reset(context?)`, `rollback`, `getState`, and `getContext`. It instantiates each of the three checkers from the same admitted World, compiles emitted TS under strict NodeNext, imports emitted Python, runs identical command sequences, and normalizes outputs to `{kind, verdict? , state, context, errorCode?}`. Compare each path separately with a hand-authored expected sequence. Normalize only known stable error prefixes such as `INVALID_BOUNDS`, `INITIAL_INVARIANT_FAILED`, `NO_CHECKER_SAVEPOINT`, and `REENTRANCY_DETECTED`; do not pretend `Error`, `ValueError`, and `RuntimeError` are the same class. Compare verdict fields, violation code/message/invariant, and the ordered diagnostic trace including accepted prefix, failed attempt, directive presence, and copied payload. The `shortestCounterexampleTrace` name remains an ordered witness, not a globally shortest-path proof.

Fixtures include: omitted/explicit-null/string directives; no directive names; empty invariants/context/transitions; sequential effects; guard, bounds, and invariant refusals; wrong and absent directives; successful step followed by refusal and failed reset; multiple successes replacing savepoint; rollback consumed; successful reset clearing savepoint; invalid constructor; malformed programmatic models; primitive and hostile request/payload cases. Change old characterization tests that assert generator defects to regression acceptance tests. The existing `kadmos test` seeded flags/report stay compatible. Extend its coverage only where a small shared command/verdict normalizer improves comparison; fixed expected fixtures are the primary oracle. Finite deterministic traces and fuzz samples are empirical evidence, not a bisimulation or compiler-correctness proof.
